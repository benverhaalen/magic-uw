# Learning and media options

Use only for a relevant selected feature. These are candidate mechanisms, not a mandatory bundle, accepted roadmap, or reason to add a new service. Start from the actual learning task and available evidence; inspect current repo/branch capabilities before implementing.

## Tailor the learning operation

Use **inventory → profile → spec → candidates → gates → deliver → observe → audit** to connect available course material and learner evidence to the activity. Build the specification from cited assessments, rubrics, lectures, and constraints; do not invent the professor's expectations. A learner profile should contain relevant evidence and uncertainty, not a presumed learning style.

Tailoring must change something consequential: the concept selected, misconception addressed, difficulty, representation, scaffold, retrieval interval, example, or feedback. Avoid a compulsory diagnostic when existing work or a brief optional task suffices. Minimize management effort while preserving productive cognitive effort.

Choose format by mechanism:

- **Reusable simulation:** prediction, controlled action, visible consequence, explanation; use when manipulating a system reveals more than prose. Inspect references such as Learn Git Branching's actual interaction before transferring it.
- **Faded worked examples / derivations:** demonstrate a useful step, then remove support as independent evidence improves. Preserve the link between each transformation and its reason.
- **Error spotting / comparisons:** distinguish plausible misconceptions or strategies; feedback should identify why the difference matters.
- **Quizzes / retrieval / spaced practice:** test the relevant skill, give specific feedback, and revisit at useful intervals. Avoid treating recall as the answer to every learning task.
- **Exam replay / rubric feedback:** reproduce evidenced task conditions without copying protected assessments inappropriately or drifting from the skill. Give rubric-linked evidence and limits, not guaranteed grades.
- **Concept maps / discussion preparation:** make relations, competing interpretations, claims, and supporting evidence inspectable. Do not flatten a humanities task into a single-answer quiz.
- **Sandbox or interactive artifact:** use when prediction/action/feedback beats reading; otherwise keep the answer short or open the existing tool.

Research educational evidence when making efficacy claims; a promising mechanism remains a hypothesis until its use here is tested. Do not use unsupported learning-style categories. Provide short feedback about what is right, the most useful gap, and a next step; use the smallest helpful hint. Keep skip, dismiss, correct, and resume available where useful without nagging.

## Keep learning evidence honest

Track exposure, hints, assistance, attempts, and relevant confidence before feedback separately. A correct answer just explained by the system is weak evidence of independent ability. Distinguish exposed/hinted performance from unseen, unassisted and delayed retrieval; match the evidence to the actual skill and assessment demands.

Initial status can be “not enough evidence.” Do not turn recorded grades, course history, model agreement, or arbitrary scores into validated readiness or a calibrated percentage. Independently solve generated questions and use executable checks when possible; a second model agreeing is not proof. Check both unwanted copying and drift from course requirements. Unverifiable items should be repaired, withheld, or clearly limited before being used to assess the student.

## Ground media in the task

For YouTube or other external explanations, verify the exact video, accessible transcript or inspected content, relevant concept, and useful timestamps. A title or search snippet does not establish fit. Keep source, access constraints, and uncertainty visible; do not invent timestamps or imply a video was watched from metadata alone.

For a student's lecture, identify an accessible, authorized recording/transcript and link the concept to a source segment. Timestamped playback/linking is different from creating and distributing a clipped media file. Check access, captions/transcript quality, timestamp alignment, rights, and retention before promising actual clipping. A failed transcript should not silently become a fabricated lecture summary.

NotebookLM-like grounded answers, audio, maps, and flashcards can live in the existing chat/workspace when they serve the journey. Investigate existing repository and branch work first, including any open-notebook inventory or prototype; such research is not an adopted dependency. Check current license, maintenance, data flow, grounding and correction behavior, operational cost, and fit before reusing an open-source mechanism. Do not add a second course store or runtime just to acquire a familiar feature list.

For any generated learning artifact or audio, preserve retrievable evidence and a return path to the relevant material. Verify grounding and usefulness in the actual task, not just the artifact's appearance or successful generation.
