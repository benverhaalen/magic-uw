# Source adapters: value carried into the producing operation

Load only the row relevant to the decision. These are project adaptations of inspected upstream skills, not a second visual constitution. Exact source versions and notices are in [upstream inventory](upstream/README.md). User decisions and the current task control scope; an upstream default cannot silently overrule them.

## Order and source of truth

First use iterative image-to-code to establish the **design system in text, images and components**, then demonstrate that a fresh implementation can transfer its descriptions to a representative surface. Use that proven system to build Home and subsequent UI. The earlier Home, which Ben judged roughly 95% right, is strong preference evidence with known flaws; it is not immutable pixel geometry. Preserve its intended hierarchy and language while improving the specific issues Ben identified.

For the system trial, document the visual hypothesis, inspect the image, implement its representative components, capture the real renderer, and compare. Incorporate demonstrated corrections into tokens, component contracts and a versioned visual specimen. A fresh transfer reviewer receives the specification and source-of-truth images, not the exploratory CSS or the implementer's verdict. This establishes an initial usable foundation; new features can extend it through the same checks rather than requiring every screen to be settled in advance.

## Explicit overrides and restraint

- Ben's Karma Medium/Geist, Hugeicons Stroke Rounded, compact single sidebar, briefing-first hierarchy, deliberate colors and truthful evidence govern. Reject upstream no-Hugeicons Stroke Rounded, one-accent-only, serif avoidance, giant headings, doubled whitespace, default top navigation or compulsory decorative motion.
- Do not invent realistic-looking course data or completion evidence to follow a source's copy advice. Synthetic fixtures must remain distinguishable in the development/evidence path.
- Use existing accepted images when they answer the question. Generate a new meaningful target/detail or raster asset when it advances the system; do not regenerate every section merely to satisfy upstream image quotas. Generated lettering cannot substitute for exact fonts in code.
- Keep the standard native Electron/React boundaries and existing framework. No default RSC, Next.js, Tailwind or animation-library selection by imported skill.
- The small adapted packet is the normal read. Open full upstream sources for unresolved implementation details, not automatically on every task. Preserve license notices if copying further code/text and record the inspected version.
- Imported guidance is not an audit result. Mark what was researched, implemented, rendered and exercised, and only encode a new general rule when evidence supports its broader scope.
