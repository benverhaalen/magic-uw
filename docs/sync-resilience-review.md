### Implemented

- Nate’s T17 scheduler and concurrent course pipelines are retained. One observed page body per run avoids redundant post-full checks; later runs still revalidate directly. Module fallback request attribution counts actual transport attempts, and shared acquisitions do not double-count. Concurrent page-list cancellation is handled immediately to prevent unhandled rejections.
- One validated module reader shared by normalization, inventory and content fingerprints. Inline items use checked pagination fallback when absent or untrustworthy; partial neighbors survive. Reuse is account/run scoped and cancellation invalidates it.
- Typed Canvas file references, including module-only and body-linked files and global/course-scoped download/preview aliases. Fresh authenticated metadata authorizes the existing document pipeline; capability URLs never become source identity. Current extraction failures replace current extracted text honestly, while history remains retained.
- Bounded nested page discovery and direct page/file revalidation cover changes that leave module membership unchanged. Successful probe components remain comparable when other components fail. A missing body cannot replace saved content with an empty success.
- Durable course-space observations and a scoped `courseSpaces` query in the existing Sources view. **Migration 9** adds `unknown` access and nullable `checkedAt`; cached content and unchanged-page reuse cannot fabricate a new successful check. Saved-copy identity follows scoped file aliases.
- String-safe Canvas requests, bounded authentication confirmation, and file scheduling that mixes urgent with older undated work. Stable denied coverage does not force a full read on every hot tick.
- External continuation traverses cached ancestors without charging them against new-page/network-attempt budgets. Default remains **300**, hard cap **1,000**. Exact evidence links retain independent uses, enforce account/course identity, and invalidate when either endpoint changes.

### Interfaces and limits

`canvas-modules.ts` supplies run-local acquisition results to `canvas.ts`, `canvas-inventory.ts`, and `canvas-selection.ts`. `canvas-references.ts` resolves exact scoped file identities. Content probes additionally expose successful per-course `components`; the refresh coordinator merges these against prior observations without treating missing signals as deletion. Desktop ingestion uses the existing document manager and storage. `course-space-storage.ts` adapts inventory/access observations; contracts/core add the scoped query. `App.tsx` mounts course-space details only in Sources.

File work starts at most 100 distinct account/course/file jobs per run, with a 120-second scheduling budget shared across initial and late-discovery drains. Page revalidation is bounded to 20 starts/60 seconds per pass. Deferred material remains discoverable from persisted links and rotates ahead of recently attempted work; these bounds do **not** guarantee every item is fresh within 15 minutes. Existing extraction/network limits still govern in-flight work. External traversal retains a 10,000-entry frontier and 120-second guard; failed network attempts stop at twice the page cap.

The course-page/notebook lane should reuse these observations rather than infer access from cached text or duplicate acquisition. Coordinate migration numbering before another schema change. Catalog-role selection and optional classifier fallback policy remain the existing implementation; this work does not add a new classifier, scheduler, login mechanism or hosted data path.

## Implementation architecture after independent review

**Accepted architecture, implemented as described above; no packaged release claimed.** This section supersedes earlier recommendations below where they differ. Baseline: Nate's pushed `f850ea7`. A fresh agent received the original request, planning skill, backend specifications and pushed code without this report or a preferred answer. Its independent review supported a shared acquisition pipeline and challenged three assumptions: increasing the crawl cap is not inherently better; an unchanged module signature does not prove linked content is unchanged; cached content does not prove current access. The driver checked the relevant code seams. Agreement is not execution evidence.

### Outcome and representative slice

From ordinary desktop launch, cached coursework is immediately useful. A student opens a current assignment while Refresh encounters denied Files, Pages and Quizzes indexes in one course. Its module-linked PDF and page-linked PDF still become extracted, searchable material with source provenance, while other courses finish. Existing Sources/course details explain the unavailable indexes separately from saved material. Restart preserves both. A later edit to linked material is either detected by successful revalidation or honestly remains stale. Real session expiry preserves saved work and offers the existing sign-in action.

The first implementation slice must demonstrate that whole path. Metadata discovery, a passing HTTP test, or a stored course-space row alone does not complete it. This improves the evidence available to existing learning features without adding hosted inference or a new learning surface.

### Decision: extend Nate's pipeline, with one acquisition result

```text
existing refresh coordinator + session owner
  → validated Canvas acquisition (scopes + modules + typed references)
  → bounded page/file resolution → existing document manager/extractor
  → existing resources, documents, passage jobs and course-space storage
  → scoped query → existing Sources/course surface and material retrieval
```

Reuse Nate's auth classifier, presence gating, hot/content cadence, storage and document machinery. Do not build a second connector, scheduler, browser agent or graph store. The consequential changes are the interfaces between those existing pieces.

**1. Shared module acquisition.** Extract one checked reader used by `canvas.ts`, `canvas-inventory.ts` and `canvas-selection.ts`. Its result contains account/course identity, observation time, validated modules/items, per-module completion and diagnostics. Request inline items/content details; accept a valid empty array, and fetch paginated items for absent/null/untrustworthy inline data. Validate child identities and counts without dropping malformed neighbors as though they disappeared. Keep existing `module-items:<id>` source semantics and deletion safeguards.

During a full/warm run, normalization, inventory and fingerprints consume that same result; a probe result can be passed into the ensuing warm read. Reuse is run-local and bound to account/session generation, not a durable permission cache. Cancellation or account change invalidates it. Independent later refreshes reobserve the server. Target module requests are list pages plus fallback pages, including inventory/probe work in measurement.

**2. Typed reference resolution.** Extend existing direct page reads with a small deterministic frontier. A reference carries account scope, originating course/source/resource, resource kind, exact native ID or page slug, safe canonical URL and discovery reason. Seed from module items and parsed assignment, announcement, discussion, syllabus and page bodies; include discoveries arriving from the existing external reader. Recognize normal file, `/download` and `/preview` routes, but discard query capabilities and never use a body-provided signed URL as download authority.

Deduplicate attempts by account, course context and native identity while retaining all where-found links in existing resources/module relationships. `course_spaces.foundInResourceId` is a representative origin, not a replacement for those relationships. Follow nested pages with a visited set and bounded depth/attempt/time limits. Scope denial of a list does not veto a known item's direct read.

Resolve a file through authenticated single-file metadata; validate identity, available course context, current locks and allowed download origin. Do not infer ownership of a global file from the referring course. Foreign-course references retain their provenance and cannot silently overwrite that course's resources. Feed the existing document manager with fresh metadata and an ephemeral download capability; avoid a second metadata fetch solely because two pipeline stages need the result. Refresh an expired capability only through the bounded existing retry path.

Remove `scope === "files"` as the exclusive document admission rule. Use validated file-bearing resources from either listing or targeted reads. Keep listed-file membership and targeted capture separate: a successful linked PDF never makes the denied Files index complete, and absence from a denied list never deletes it. Preserve existing file/document identities and extraction reuse. Run a bounded follow-up drain for late references in the same refresh; unfinished work stays discoverable for continuation after restart through persisted resources/spaces. No separate durable job platform is required.

**3. Persist access evidence through an explicit adapter.** Connector `CourseSpace` and canonical storage `CourseSpace` are different types; wiring `onSpaces` with a cast is insufficient. Add a tested adapter that maps route/read-state enums, derives account/course from the trusted source, validates referenced resources belong to the allowed context, and includes account scope in durable space identity. Persist from the real worker, hydrate on restart, and expose a scoped query rather than expanding the full snapshot.

The canonical contract currently requires a non-null `checkedAt` and has no unknown access state, while discovery can have no access observation. Add explicit `unknown` plus nullable access-check time through the next available coordinated schema migration; do not invent a successful check timestamp. Migrate any existing ambiguous data conservatively. Keep discovery, latest access attempt, last successful capture and freshness separate. Existing source/capture records retain scope history; course spaces retain item/route observations. Partial inventory merges cannot delete previously discovered spaces. Only a complete relevant enumeration can reconcile membership.

An item is readable because its own read succeeded, not because old text exists or its list succeeded. A failed list does not establish that each item is blocked. Cached material remains available even if its latest access is denied or unknown. Derive course summaries from these observations; an aggregate latest timestamp cannot imply all items were checked then. In existing course/Sources details, use wording such as “Files list unavailable; 3 linked files saved” with per-scope detail and the existing refresh/sign-in actions. This is a behavioral contract; rendered design must follow Magic design guidance during implementation.

**4. Freshness as successful observation, not a weak hash.** Keep the scheduler; use shared module fallback in content probes, including same-count replacement/retitle cases. Malformed list responses are unknown, never an empty success. Preserve successful component signatures when another component fails, and advance each watermark only after its relevant observation succeeds.

Structure hashes cannot detect edits inside an unchanged linked page/PDF when indexes are denied. Add bounded direct revalidation of known linked items, prioritizing current assignment dependencies, then a fair rotating remainder. Retain last successful check per item so restart does not continually favor the same items. Use a cheap trustworthy version field when available; if metadata cannot establish unchanged content, require a successful read before claiming it current. Do not assume ETag support without observing it.

Keep five-minute dated and fifteen-minute content scheduling while present as Nate's targets. A detection guarantee applies only to items actually observed within the budget; deferred/failed items display older freshness. Retain the six-hour full backstop, and reconcile the spec's older ten-minute full-refresh wording when integration is authorized. Stable restriction remains incomplete coverage but is not transient failure: retry on manual refresh, relevant inventory/identity change and bounded backstop; retain the existing thirty-minute retry for transient failures. Confirmed expiry stops authenticated work until the existing recovery owner resumes it.

**5. Preserve auth behavior; harden evidence precedence.** Keep scoped unauthorized handling and the bounded nonrecursive profile confirmation. Add regression cases for explicit unauthenticated JSON on 403, sequential suspicious responses, and unexpected redirects with a healthy profile. Explicit auth evidence must reach confirmation before a generic permission classification. Bound repeated inconclusive confirmations within a run and stop that run as partial when its confirmation budget is exhausted; never convert exhaustion into logout. A successful prior profile check is not indefinite proof against later expiry. Preserve immediate handling of new explicit auth evidence and account-generation changes.

### Ordering, budgets and small decisions

Priority is deterministic: newly requested/manual material and near-term assignment dependencies first, syllabus/schedule next, then remaining course references with fair progress. Specify the overdue window in policy and tests; do not let all historic overdue work outrank current material. Carry priority through assignment → page → file identity, not exact URL string equality. Reuse existing concurrency, byte limits, allowlists and extraction cache. Budget attempted requests as well as successful pages, bytes, elapsed time and queue growth. Cancellation saves completed observations and leaves explicit partial work.

**Revision to the earlier 1,000-page recommendation:** unify contract/runtime limits and preserve saved settings, but retain the current 300-page default for the initial slice. Evaluate 1,000 as an explicit bounded trial after priority and continuation exist. Promote it only if matched courses show more useful instruction material without unacceptable foreground delay or traffic. This follows Ben's permission to use judgment and the fresh review; neither source established 1,000 as an optimum.

Request string IDs consistently in the direct HTTP path and desktop main transport; test IDs above the JavaScript safe-integer limit through the bridge. Defer catalog syllabus slimming until course details reliably produce syllabus and seed links early; compare bytes and first-useful-content latency. Keep concluded-course metadata, selection reasons and explicit inclusion overrides. Add current-term/active-enrollment contradiction cases and a bounded read where inclusion warrants it; do not globally ignore conclusion or enroll historic courses automatically.

Quiet SSO recovery, remembered passwords and automatic login windows remain outside this slice. Ben's conditional mechanism and Nate's open H2/H3 choices do not justify silently choosing a new recovery policy. Continue with existing student-invoked sign-in; no new account interaction is needed to implement the acquisition architecture.

### Nuances that change the implementation

Planning-skill follow-up: the objective is usable, correctly scoped course evidence with less student repair, not a larger inventory. These are proposed refinements to the architecture, grounded in the existing source/version, exact-link and consent rules in [course intelligence](course-intelligence.md), [pipeline details](pipeline-details.md) and [decisions](decisions.md#pricing-and-ai-access-resolution--september-26). They do not claim new implementation or live verification.

| Distinction | Required behavior and discriminating check |
| --- | --- |
| Found → downloaded → extracted → indexed → usable | Track stage outcomes separately. A saved scanned PDF with no extractable text is available to open, but cannot count as searchable support. Exercise extraction failure and unavailable OCR; preserve the original and avoid automatic hosted fallback. |
| Reference versus authority | A link establishes where a material was found, not that it is required, current instructor policy, or applicable to every assignment. Preserve relation and scope; keep direct versus transitive provenance. A syllabus reference can raise collection priority without granting policy authority to the linked text. Test an optional reading beside an explicit assignment specification. |
| Deduplicated acquisition versus distinct uses | One PDF can support several assignments. Fetch/extract once within an authorized identity boundary while retaining each relationship. Removing one link must not remove other uses. Identical bytes across courses do not authorize combining their context or grants. |
| Updated source versus updated dependent result | A new PDF version must invalidate its old passages and dependent claims through existing source hashes/jobs. Keep old captures distinguishable from current evidence. Reject extraction results that arrive after a newer capture, account change, exclusion or purge. Test a file changing while extraction is running. |
| Changed relationship versus deleted material | If an assignment replaces its PDF link, remove the obsolete current association only after a successful observation of that assignment; retained historical material can remain. A failed assignment read cannot establish that the old association disappeared. Preserve user-rejected associations across rediscovery according to existing correction rules. |
| Coverage versus freshness | A recently checked module list says nothing about uncaptured items behind a restricted index. Report scoped counts and known limits, not a whole-course percentage with an unknown denominator. An unchanged weak signal cannot refresh an item's timestamp. |
| Metadata refresh versus content refresh | A refreshed title/URL may leave content unchanged, while a replacement file can change passages behind a stable link. Cache extraction by validated content identity and extractor version; refresh source metadata independently. Do not treat an expiring download URL as a new document version. |
| Urgency versus starvation | Due-soon links deserve priority, but undated readings, labs and exam preparation still matter. Reserve progress for the remaining frontier; explicit student requests take priority. Submission can lower routine acquisition priority without implying no future need for feedback/revision material. Exercise a non-CS course with mostly undated readings. |
| Partial work versus endless work | Resuming a frontier must not restart the same first pages or repeatedly hammer a stable denial. Persist enough identity/check state to advance fairly, bound queue growth and retries, and cancel obsolete work. Test restart after a budget stop and a cycle of nested pages. |
| Local availability versus permission to share | Resolving more attachments must not quietly widen provider/MCP context. Carry source course/category and applicable restrictions into retrieval; recheck grants at request time. A chain through a course page cannot strip a sensitive attachment's classification. Test revoked grants and newly encountered sensitive material. |
| Useful recovery versus extra management | Keep saved material immediately usable. Offer sign-in for confirmed expiry, retry for transient failure, and an original-source link when content cannot be processed. Stable denied indexes should not repeatedly interrupt the student. Course-level detail is the explanation surface; do not add a new dashboard or ask students to manage crawl settings routinely. |
| Early usefulness versus misleading speed | Measure time until the assignment's actual dependencies are usable, alongside total requests/bytes and deferred work. A faster first assignment record or more discovered URLs is insufficient. Compare the same representative fixture/course conditions, including denied lists and extraction failures. |

The smallest additional proof beyond the original representative slice is a PDF replacement during extraction, a saved but unextractable document, one document with two assignment links, and an undated-reading course. These distinguish a robust implementation from one that only passes the clean linked-PDF example. The depth and revalidation budgets remain tunable implementation parameters; choose them from matched measurements rather than inventing a universal coverage guarantee.

## What the implementation investigation established

### 1. Scope denial currently aborts the whole run

`CanvasHttp.request` in [canvas-http.ts](../packages/connectors/src/canvas-http.ts) expires immediately on 401, redirects, off-path/off-origin responses, and HTML; a non-rate-limit 403 also expires. `expire()` aborts the controller shared by requests in that HTTP instance. Course loops in [canvas.ts](../packages/connectors/src/canvas.ts) stop when `needsSignIn` becomes true. [ingestion.ts](../apps/desktop/src/ingestion.ts) then marks all Canvas sources as needing sign-in and skips document ingestion; [refresh.ts](../packages/core/src/refresh.ts) delays authenticated retries for three intervals.

Direct synthetic experiments against the unchanged implementation confirmed:

| Injected response | First request | Next unrelated request | Actual fetches |
| --- | --- | --- | --- |
| 401 JSON `status: unauthorized` | needs_sign_in | needs_sign_in | 1 |
| 403 JSON `status: unauthorized` | needs_sign_in | needs_sign_in | 1 |
| 401 JSON `status: unauthenticated` | needs_sign_in | needs_sign_in | 1 |
| 200 HTML temporary-error page | needs_sign_in | needs_sign_in | 1 |

Using `createSyntheticCanvasUniversity`, fixed time `2026-09-26T15:00:00Z`, no-op sleeps, and deterministic jitter, the normal connector run made **80 requests**, completed **five Files scopes**, and completed **five Assignments scopes**. Intercepting only `/courses/101/pages` with a 401/unauthorized body produced **35 requests**, **zero complete Files scopes**, five complete Assignments scopes, and a sign-in result. This establishes the failure mechanism, not its frequency at UW. These counts exclude downstream document downloads and are not latency measurements.

Upstream corroboration: at Canvas commit `1c9f0bb8013ed69c4f2efe11fd483025469b7e6c`, [`render_json_unauthorized`](https://github.com/instructure/canvas-lms/blob/1c9f0bb8013ed69c4f2efe11fd483025469b7e6c/lib/authentication_methods.rb#L413) returns **403/unauthorized for an authenticated user**, and **401/unauthenticated when no user is authenticated**, with `WWW-Authenticate` on the latter API path. Other response paths exist. Support both 401 and 403 permission errors rather than assuming UW runs exactly this upstream revision. Body status is useful evidence; message wording and HTTP status alone are insufficient.

The proposed mechanism is failure isolation: permission failures terminate only their scope; a confirmed account-session failure stops authenticated work. Microsoft's [bulkhead pattern](https://learn.microsoft.com/en-us/azure/architecture/patterns/bulkhead) supplies the architectural analogy, not a new framework. The transfer is the scope/account distinction in the existing cancellation path. It fails if permission errors can still reach the shared abort or if real expiry keeps dispatching requests.

**Required details when reviewing T05c:** share one in-flight confirmation across concurrent failures; avoid recursively confirming the profile request; avoid waiting for a pool permit while every permit is occupied by requests waiting for confirmation. Use a bounded confirmation path with cancellation and the same origin/identity checks. A valid profile means the original permission failure is inaccessible and odd HTML is partial. A network timeout, 429, or 5xx from the profile is inconclusive. Recognized login redirects remain authentication-failure evidence; never follow arbitrary origins with Canvas credentials or save HTML as coursework. Confirm before presenting account-wide expiry, and preserve an inconclusive state when confirmation cannot establish it.

### 2. Hidden navigation and inaccessible content are distinct

The [Tabs API](https://canvas.instructure.com/doc/api/tabs.html) describes navigation visibility, not proof that every underlying resource is inaccessible. Current source also differs by endpoint: [`WikiPagesApiController#index`](https://github.com/instructure/canvas-lms/blob/1c9f0bb8013ed69c4f2efe11fd483025469b7e6c/app/controllers/wiki_pages_api_controller.rb#L296) checks the Pages tab, while [`FilesController#api_index`](https://github.com/instructure/canvas-lms/blob/1c9f0bb8013ed69c4f2efe11fd483025469b7e6c/app/controllers/files_controller.rb#L353) authorizes folder contents. Therefore the reported folders-without-files pattern is a useful lead, not sufficient proof of its cause.

Reuse Nate's D32 inventory and D41 access display. Add the tabs GET to the explicit URL allowlist; it is not currently allowed. Record navigation visibility independently of observed list/detail access. Do not suppress a linked page/file solely because its tab is hidden or absent. Only use “hidden in course navigation” when the captured tab evidence supports it; otherwise use “access restricted.” A changed tab or successful targeted read should clear the corresponding stale restriction.

A further integration issue: `hasIncompleteRead()` treats any non-ok included source as incomplete, and `refresh.ts` clears the probe signature when a full read is incomplete. Merely changing permission errors to inaccessible would therefore keep requesting full refreshes. Keep coverage honest while tracking stable restrictions separately from transient retry work; recheck restrictions on manual refresh, relevant inventory change, and bounded cadence. Do not mark an inaccessible source complete to obtain scheduling benefits.

### 3. Inline modules are a small, useful change

The module request lacks both includes, and `moduleSchema` currently discards inline `items`. The [Modules API](https://canvas.instructure.com/doc/api/modules.html) explicitly supports inline items and requires fallback when omitted. The inspected [serializer](https://github.com/instructure/canvas-lms/blob/1c9f0bb8013ed69c4f2efe11fd483025469b7e6c/lib/api/v1/context_module.rb#L59) counts visible items and emits them only below its limit. Do not hardcode that server threshold.

Extend parsing and reuse existing item normalization and `module-items:<id>` scopes for both paths. Distinguish absent/null from a valid empty array; reject mismatched module identity, duplicates, malformed items, and suspicious count mismatches without asserting complete removal. Fall back through checked, paginated URLs. A malformed child must not discard unrelated modules.

Request model: before = module-list pages + all per-module item-list pages; after = module-list pages + fallback item-list pages. The measured synthetic baseline used **5 module-list + 5 item-list requests**. With all five modules inline the projected count is 5, saving 5 of 80 connector requests. This is a calculation, **not a measured after result**. Large-course fixtures must cover multiple module-list pages and multiple fallback pages. Measure bytes and useful arrival too; larger responses can offset some request savings.

### 4. File discovery must reach download admission

[ingestion.ts](../apps/desktop/src/ingestion.ts) admits documents only when `r.file.id` exists and the source scope equals `files`. A module item's `contentId` is stored but does not satisfy that predicate. The page parser already preserves stable file identity when removing verifier URLs; simply finding that link does not enqueue the download.

Implement one bounded discovery queue keyed by account, course, and file ID. Feed it listed files, File module items, and safe Canvas file links from all requested body sources. Preserve each discovery edge; deduplicate the download. Resolve metadata through the [single-file GET](https://canvas.instructure.com/doc/api/files.html), validate exact identity and available course context, then use the existing document manager. A foreign-course URL must not silently become a file belonging to this course. Global file links need explicit provenance and must not assert an ownership field the API did not supply.

Recheck `locked_for_user`/lock evidence in fresh metadata immediately before downloading: the current downloader validates only ID and URL at that point and relies on the earlier list's lock value. Keep byte/concurrency limits, allowlisted download origins, local extraction, cache reuse, and ephemeral capabilities. Never fetch a signed URL copied out of page content as authority; obtain fresh metadata through the authenticated API.

Use actual discovery edges for priority: assignment → page → file should inherit near-term priority. Today's priority uses exact URL equality and includes overdue items without a lower date bound. Use canonical file identity and an explicit overdue/near-term policy. Ensure syllabus and announcement links, nested page links, and pages discovered during external crawling reach the queue; the current `gather` call sites only seed pages from assignments and module items. Run a bounded follow-up drain for late discoveries instead of waiting silently for another refresh. Preserve list coverage as inaccessible even when specific linked files are successfully captured.

### 5. External crawl: 1,000 is reasonable as a bounded proposal

The contract defaults to 300 with a maximum of 1,000; `external.ts` separately defaults to 300 and clamps to 2,000. Reconcile both, preserve saved user choices, and propose 1,000 as the new default and common maximum for this slice. Keep depth, folder/host restrictions, robots, DNS/SSRF protection, download bounds, and partial diagnostics.

Prioritize due-soon instruction links, syllabus/schedule links, then remaining course material, with deterministic breadth-first traversal within each tier and fair progress across courses. Do not add model ranking. A page cap alone is insufficient: current `pages` counts successful/cached pages rather than every failed attempt. Add an explicit request/attempt and elapsed-time budget, deduplicate before queue growth, and retain partial captures at cancellation or a budget stop. A 1,000-page sequential crawl can still be slow; saved coursework and early Canvas results must remain usable.

Measure capped-versus-complete useful material, first useful instructions, attempted requests, bytes, elapsed time, and the cap/depth/robots reasons. Reconsider 1,000 if the extra pages rarely add useful material or delay urgent evidence. The budget value is a proposal; no real-course optimum was measured.

### 6. Session recovery needs an explicit reconciliation

Distinguish diagnosing authentication from renewing it. A single profile check diagnoses failure; it should not open a login window. Ben's optional quiet reload would perform a bounded reauthentication attempt using an existing SSO session. Mechanically that differs from periodic keepalive, but compatibility with UW behavior has not been demonstrated and Nate's T05c explicitly excludes a hidden window.

Recommendation for the shared slice: take Nate's scoped-error/profile-confirmation work and presence gate, preserve saved coursework, and reuse his sign-in owner. His latest H2/H3 explicitly leave remembered credentials and automatic window opening for reconciliation; direct reconnect remains the shared fallback. Do not add a second hidden recovery implementation beside his sign-in owner. If quiet recovery remains desired, reconcile T05c's acceptance first and test a single app-owned navigation followed by profile/identity validation, stopping at login/Duo, timeout, cancellation, or account change. No password storage, cookie restoration, expiry extension timer, or Duo automation is required for that experiment. Nate's D39 password feature stays a separate opt-in capability, not an implicit consequence of this task.

### 7. The three smaller changes

**String IDs: recommend.** The [API overview](https://canvas.instructure.com/doc/api/index.html) specifies `Accept: application/json+canvas-string-ids`. `canvasId` already accepts strings and rejects unsafe numbers. But the worker drops `RequestInit.headers`, and `main.ts` sets its own Accept header: a connector-only edit would not change actual desktop requests. Set the fixed Canvas Accept policy in the main transport and direct connector path; test profile, pagination, content IDs, and IDs above JavaScript's safe integer limit. Check actual response content-type parsing too. [Object IDs](https://canvas.instructure.com/doc/api/file.object_ids.html) documents SIS/special aliases; this change does not require permitting those aliases or weakening numeric URL validation.

**Lighter course catalog: recommend after ordering changes.** Course details already request `syllabus_body`, but the early phase immediately calls `syllabus(course)`. Removing the catalog include alone creates a spurious missing-field partial result and delays syllabus link discovery until late details. Make details the explicit syllabus producer, prioritize them early, retain cached syllabus, and avoid marking an intentionally unrequested field as a failure. Compare payload bytes and time to useful syllabus, not only request count.

**Concluded courses: real exclusion risk, not measured UW loss.** A synthetic course with active student enrollment, current academic term, published workflow, and `concluded:true` scores 5.5 but is excluded. The [Courses API](https://canvas.instructure.com/doc/api/courses.html) and upstream [`soft_concluded?`](https://github.com/instructure/canvas-lms/blob/1c9f0bb8013ed69c4f2efe11fd483025469b7e6c/app/models/course.rb#L2389) show that conclusion can depend on course/term dates. It is not synonymous with inaccessible content. Recommend separating academic relevance, participation state, and read access. An actively discovered, current-term course with contradictory conclusion metadata merits a bounded read-only access check and visible conflict; actual access restrictions still win. Historical-only catalogs remain metadata-only by default. Do not promise the current classifier can never drop an active class.
