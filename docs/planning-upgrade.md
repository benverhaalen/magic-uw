# Planning integration

Updated September 26, 2026. This is the implementation and evidence handoff for the authorized planning brief, alongside [course ingestion](ingestion-upgrade.md). The desktop now reads student planning data through bounded UW adapters and stores it locally. **The full planning vision is not complete:** combined schedules, natural-language planning, transcript ingestion, and broad program coverage remain unfinished. See [implementation status](implementation-status.md) for integration checks.

## Student journey and current boundary

The student opens **My UW**, sees saved evidence immediately, refreshes current enrollment and saved degree audits, inspects remaining requirements, and loads course offerings and sections for comparison. Holds and enrollment appointments also appear on Home. A failed refresh preserves old evidence and shows its age/health. The student makes academic decisions and completes enrollment in [Course Search & Enroll](https://enroll.wisc.edu/).

Accepted primary navigation is **Home / Courses / My UW**, with the Wisconsin crest; Email is deferred. Sources and Data & AI remain utilities. This addition preserves the existing renderer; the separately documented Home visual exploration is not implemented by this change.

Comparison returns **individual course/package options**, ordered by evidenced requirement progress and then schedule fit. Historical grades are optional evidence, never a ranking target. Balanced, mornings, compact, and fewer-credits-per-course preferences act on individual options; they do not produce a combined schedule or verify a lighter term load. Calendar animation/export, streamed explanations, and natural-language requests remain future work.

### Live observations, September 26

The integrated native HTTP client → UW adapters → SQLite → close/reopen path succeeded on one authorized account, with zero normalization rejects. Enrollment, primary degree-plan history, saved audits, account binding, and source health were exercised. Private inventory counts, course identities, report contents, grades, and timings remain outside this public repository. No hosted model received this data.

Saved audits remain **partial** where report blocks lack a supported interpretation. Degree-plan history leaves transfer/test rows without reliable canonical identity unresolved. Observed explicit empty holds/advisors lists are complete empties; nonempty shapes not covered by the adapter remain partial. The latest saved report is selected independently per institution/program/honors scope; ambiguous ordering stays partial. Reports are never generated by the app.

Separate bounded public API checks found 99 courses for one subject, 72 for another, and 73 open-course matches in the first subject, each paginated at 50. A selected course returned nine enrollment packages with 27 meetings; a topic-suffixed course returned one package. These checks establish those request/response shapes, not availability for every course. Search text was observed to be broad full-text matching, so code never treats a query for a number as an exact catalog-number filter.

Public HTML observations yielded 187 Registrar subject rows, three corroborated terms, and 137 Guide courses plus 60 explicit cross-list records in one subject, with one unparsed block. This is different source coverage from the 190-entry service map, not proof either source is a full substitute. Initial anonymous probes returned 403; subsequent authorized session-backed reads succeeded. The cause of the earlier 403 and anonymous reliability are not established.

The private checks used Ben's explicitly authorized Firefox UW session **headlessly for development only**. Cookies remained local; private captures, identity, grades, and course details are outside Git. The product has no personal-browser cookie importer. App-owned sign-in/SSO and session-expiry behavior still need a real end-to-end check; this developer transport does not prove that onboarding journey.

## What each academic source can establish

| Source | Supported interpretation | Do not infer |
| --- | --- | --- |
| Canvas | Accessible course metadata and separate current/final gradebook letters and percentages; active coursework when readable. | Complete enrollment history, official grades, credit earned, degree completion, or mastery. A restricted/missing Canvas course is a coverage gap. |
| Degree plan / current enrollment | Source-recorded attempts, grades, credits, and in-progress/planned states, with term and identity evidence. | An official transcript or GPA eligibility where the source does not establish it. Unidentified transfer records stay unresolved. |
| DARS | How one saved program audit applies courses and credits to its requirements, including incomplete/conditional/unknown blocks. | Another program's approval, extra earned credits for repeated appearances, universal double counting, or an authoritative transcript. |
| Unofficial transcript PDF | A dated Student Center academic-record snapshot when read and validated. | Current data merely because an older report was downloaded today; no automatic production comparison is implemented yet. |
| Public catalog / historical grade distributions | Published course descriptions, exact explicit equivalences, and separately sourced historical grade counts. | A current offering from a description, personal expected grade from a distribution, or professor quality from grade averages. |

[UW identifies Canvas grades as unofficial until posted to Student Center](https://registrar.wisc.edu/student-grades/). [DARS is a program-specific audit](https://registrar.wisc.edu/dars/). Preserve both distinctions in data and UI.

The local reconciliation projection requires a fresh **verified same-account link**, exact course identity, and an exact term. Canvas academic-year labels require corroboration from the course code. It keeps each source claim and citation; it never overwrites one with another. Current/final scores remain distinct, percentages never become letters, repeated attempts in different terms remain separate, and duplicate DARS appearances do not create extra attempts. Credits explicitly carry an `attempt` or `audit_application` basis; varying applied credits are labeled separately from conflicting attempt credits. Unknown/stale claims remain visible with verification limits.

A private saved-data replay exercised active, historical, and restricted Canvas entries, exact matches, unmatched academic attempts, and unresolved Canvas identities. Letter-grade comparisons and applied-credit variations remain separate from attempt-credit differences. This is **not evidence that all Canvas grades agree with the transcript**, and none of these results establishes readiness. Personal counts, values, and findings stay in the private validation record. Transcript integration must preserve dropped rows, unresolved transfer/test designations, and differing term placement without inventing equivalence. Report placement does not establish original attendance. Blank transcript grades alone are not an in-progress flag—current enrollment must corroborate that state.

## Facts and uncertainty stay in code

- **Terms:** `1262` → Fall 2025, `1264` → Spring 2026, `1266` → Summer 2026, `1272` → Fall 2026. DARS catalog `20251` is **Fall 2024**, while course label `FA24` names calendar Fall 2024. Separate tested codecs prevent mixing these formats. [Official DARS encoding](https://kb.wisc.edu/ac/162248).
- **Identity:** numeric subject + catalog number, authoritative aliases, and explicit cross-list evidence. Conflicting mappings stop comparisons; a similar name is insufficient. Topic-suffixed offerings remain distinct catalog objects.
- **History:** completed, in-progress, planned, dropped, withdrawn, and unknown states remain separate. Unknown grades/incomplete history cannot silently satisfy prerequisites. Retained history guards against suggesting an already taken course without establishing current eligibility.
- **Meetings:** UW service clock fields use an observed fixed six-hour decoding offset; calendar dates use America/Chicago. Code handles date overlap, weekday overlap, and times independently. Unknown/asynchronous meetings are explicit. Unknown dates/times cannot establish a conflict-free schedule, even against an empty calendar. Another term's enrollment cannot clear the selected term.
- **Audits:** unknown blocks are retained; INP/TI do not become completed work. A timezone-less report generation time stays unknown with its original evidence. Select-from matches are potential coverage, not approval. The ranker does not invent prerequisite-unlock counts or cross-program double-count rules.
- **Grades:** count-weighted A/AB/B/BC/C/D/F averages use 4/3.5/3/2.5/2/1/0 with included/excluded counts. This is an average, not a median or prediction. Attempt GPA requires known eligibility. Ambiguous aggregates are omitted rather than arbitrarily combined.
- **Freshness:** current one-day source and seven-day audit/prerequisite windows are conservative application heuristics, not measured UW validity periods or session lifetimes. Stale seats/eligibility are withheld; missing generation timezone requires verification.

## Storage, privacy, and access

Planning has separate source/record/version tables in SQLite schema 4. Source health is keyed by **source + account scope + scope kind/key**. Only a successful complete capture can establish removal. Partial/failing/blocked reads preserve old records and cannot advance complete success. Old captures, conflicting identities, mixed scopes, and term mismatches are rejected or explicitly incomplete.

Public records use scope `public`. Private account scope is a local keyed hash of the verified student identity, checked again before releasing normalized results. Canvas and UW identities are compared inside the native broker; only an opaque account link crosses into storage. Names, NetIDs, email addresses, and student IDs used for this check are not stored in the link. Account changes invalidate the result. Multiple saved private accounts block comparison rather than combine students. Clearing the session rotates its scope seed; reconnection may therefore require removal of old local data to resolve multiple saved accounts.

The typed student summary omits identity fields; this is not a general free-text anonymizer. The local database is permission restricted, not app encrypted. Credentials/private source bodies stay out of logs and Git. Clearing the UW session preserves evidence with disconnected health; deleting local data removes planning records and prevents late jobs restoring them.

**All planning records are excluded from hosted AI, Jev, local tutoring context, and MCP**, including public catalog records. Reserved `sharePlanning`, `shareHolds`, and `shareAudit` flags default off and do not enable egress. Coursework grade sharing does not expose planning grades. Future sharing requires audited category-specific projections and actual-recipient/payload previews.

The native operation allowlist has no enroll, drop, swap, waitlist join, cart addition, transcript generation, or audit generation. One bounded public-search POST is a read; HTTP method alone is not the authorization boundary. Same-host redirects/headers, response bounds, cancellation, retry limits, and host pacing are enforced. Two-second pacing is a precaution, not a measured UW rate limit. Never automate Duo or send keepalive traffic.

## Requirements still open

- **App-owned onboarding:** embedded NetID redirect/SSO completion, session lifetimes, expired-session recovery, identity switching, and Windows behavior. The lightweight [Search reference](https://github.com/driceroland/Search) uses a persistent WKWebView; it informs compact sign-in UX, not an adopted replacement for Electron.
- **Representative coverage:** non-CS loads, college/program audit variants, transfer equivalences, nonempty holds/advisors, topic prerequisites, professional grade rules, and partial report blocks.
- **Planning engines:** combined schedule solver, verified prerequisite-unlock graph, double-count constraints, personal load limits, richer policy alerts, proposed-calendar export, and natural-language explanations.
- **External evidence:** Madgrades token/live adapter and parameter checks. Professor ratings remain link-out; no rating scrape or imported rating dataset. No coursemap code/data was adopted.
- **Transcript:** existing report access was demonstrated, but a safe production parser and source/attempt reconciliation need a separate implementation. Download time cannot replace the report's print date.

### Selective Madgrades backend port — September 26

The historical-grade adapter and `planning-grades` command have been adapted to current main's protected host vault and consent/cancellation seams. `madgrades-token` is handled only by the desktop host; the worker receives fixed request shapes. Public course identities use only public subject/cross-list evidence. Purge cancels reads and late replies cannot recreate planning records. Historical averages remain optional comparison evidence and do not affect recommendation order or enter AI/MCP context.

This is a partial backend capability: no token setup frontend or normal student entry has been added, and API compatibility remains synthetic-fixture tested, not verified against a live authenticated response. No private data or credentials were used. Focused tests cover exact identity, ambiguity, account separation, cancellation/purge, token non-disclosure, averaging and unchanged comparison ordering. The host retains current setup-consent gating for public planning reads; a complete setup journey still needs an explicit Madgrades destination disclosure.
