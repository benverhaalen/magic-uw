# Tool evaluation — September 26, 2026

This is a source audit and a set of testable choices, not a measured performance ranking. Release dates below came from the repositories' live release metadata. A recent push does not prove a recent stable release or good maintenance. Versions must be pinned when an adapter is adopted. General selection rules live in [engineering principles](engineering-principles.md).

## What we are choosing for

Our priority is correct, attributable course evidence with little student effort. We must retain dates, tables, code, attachment links, policy exceptions, and source scope. Acquisition, main-content selection, structured extraction, OCR, and change monitoring solve different problems; comparing their speed as though they were interchangeable would mislead us.

The implemented adapters read structured Canvas/GitLab JSON, public HTML and embedded JSON, calendars, and local documents. Scoped HTML extraction uses htmlparser2; the bounded public crawler preserves links and embedded data without executing scripts. A general main-content or JavaScript rendering engine remains a separate decision. Browser access is injectable; adding another engine should not change storage, deadlines, or privacy rules. See the [ingestion handoff](ingestion-upgrade.md) for current behavior.

## Concrete adoption gate

For each adapter, record: exact version/license and model license; local-only or disclosed destinations; representative corpus and expected fields; retained quotes/links/table relations; blocked/partial detection; measured cold/warm time and memory; known failure cases; reason it beats the baseline; rollback trigger. Reject outputs that lose provenance or silently turn a failed capture into empty data. No candidate in this note has yet passed a broad UW course-corpus evaluation.
