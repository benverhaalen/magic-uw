# Course ingestion

Updated September 26, 2026. This describes the ingestion upgrade in code. Upgrade checks use synthetic data; the expanded app-owned UW path and its live performance remain unverified. An earlier thin-connector pull used a now-retired adapter and does not validate this path. See [implementation status](implementation-status.md) for application acceptance results and [AI and privacy](ai-and-privacy.md) for the broader privacy model.

## Student journey

The desktop starts with an empty local workspace and hosted sharing off. The student completes UW sign-in in the app-owned browser session, then refreshes. Account activity arrives first, followed by assignments, modules, announcements, referenced instructions, and supporting material. Each source shows its own progress and freshness; usable earlier coursework stays available during a failed refresh.

Course selection uses active enrollment, academic term, catalog code, and site-name evidence. The student can filter by term and correct an inclusion decision for that account. Excluded spaces retain their name and reasons, while their material is not enriched. A course absent from a later complete active-course list becomes excluded without deleting its saved coursework. Nameless date-restricted courses remain identifiable by course ID and access state.

Background refresh defaults to ten minutes with 20% jitter, quiet hours from 1–6 a.m. local time, and suspend/resume handling. Calendar feeds are checked independently. An activity-summary probe avoids a full Canvas read when unchanged; public material has a six-hour refresh interval. Manual refresh bypasses those scheduling shortcuts. After expiry, the student signs in again; the app does not automate Duo.

The academic score includes active student enrollment (+1), published course (+0.5), academic term with year (+2), and catalog code (+2). Default/ongoing terms subtract 1; noncourse name clues subtract 3; a missing name subtracts 1. The default threshold is 3. Access restrictions and selected term are separate checks; a score is a transparent heuristic, not a claim about course quality.

PDF extraction runs locally with PDF.js and retains page anchors. Local converters handle DOCX/PPTX/XLSX, ODF, HTML, text, Markdown, CSV, JSON, and notebooks; slide/section evidence is retained where available. Downloads are limited to 100 MiB, and extraction to 500 parts/pages and 200,000 characters. Unsupported or textless content has an explicit status. The local OCR adapter accepts installed Poppler/Tesseract components and gates OCR to urgent or opened textless pages; the desktop can wire it through explicit `MAGIC_PDFTOPPM_PATH`, `MAGIC_TESSERACT_PATH`, and `MAGIC_TESSDATA_DIRECTORY` settings. These tools and trained data are not bundled; real OCR has not been demonstrated in this environment.

## Evidence and failure semantics

`CaptureBatch` identifies account, course, and source scope, then carries an observation time, resources, status, completeness, diagnostics, and request/progress statistics. Resources preserve raw markup where available, normalized text, safe links, typed metadata, and page/slide/section locations. SQLite keeps content versions, per-field observations, source health, and deterministic change events. Omitted fields retain prior observations; explicit empty and null values are observations.

Each incoming record is validated separately. One malformed assignment does not discard valid neighbors. Diagnostics contain field paths and codes, not rejected private values. A paginated scope stays partial until all its pages succeed. Only a successful complete scope may establish removal; expiry, malformed responses, bounds, inaccessible sources, and transient failures cannot erase prior coursework. Restored items remain distinguishable from newly added ones.

Canvas scopes use `per_page=100`, with limits of 20 pages/2,000 records, 8 MiB per response, a 15-second request timeout, and a two-minute scope timeout that starts when the scope's first request holds a scheduler slot (queue time behind other scopes does not count). A scope still queued when the run stops is recorded as `scope_deferred` (partial, warning), not as a time limit. Metadata concurrency defaults to 8; download concurrency to 4. Request-cost and remaining-budget headers influence pacing. HTTP 429 and rate-limit 403 responses receive at most four retries with backoff and jitter; exhausted rate limits remain partial. Authentication failure aborts the shared Canvas reader and stops new requests while retaining earlier validated records.

Exact same-account/course URLs connect instructions and calendar evidence to assignments. Due dates and lock dates remain different. A grade does not establish submission without submission evidence. There is no model call in ingestion or deterministic change detection.

## Access and privacy boundaries

Canvas access is a narrow GET allowlist for documented endpoints and query parameters. Paging must retain origin and scope. Only the main process attaches the app-owned Canvas session; connectors cannot copy credentials or attach personal browser cookies. External fetching uses a separate credential-free transport with public-address validation and DNS pinning on every redirect. GitLab has its own fixed-origin GET boundary and session/token mechanism; UW sign-in is not assumed to authenticate GitLab.

Calendar feed URLs are capabilities: discovery sends them directly to encrypted secret storage through a dedicated callback. Signed download URLs stay transient. Neither belongs in coursework records, diagnostics, source IDs, MCP output, or cloud context. URL-pattern sanitization covers captured markup/text and decoded embedded JSON; it is not general detection of secrets written in prose or a rewrite of downloaded binary documents. The coursework database and downloaded files themselves are local, permission-restricted storage, not app-encrypted storage.

Grader comments are collected locally by default in the typed submission field, separate from ordinary instruction text. Turning collection off stops future comment reads and retains already saved feedback until local deletion. Grades, comments, student work, communications, and course text have separate sharing gates. MCP connections additionally require an explicit recipient, course selection, category grants, and a revocable local credential; enabling local collection does not grant cloud access.

## What has been checked

- **Canvas:** 33 passing connector tests, including a synthetic university with five academic classes, five noncourse spaces, one restricted nameless course, empty assignment descriptions with linked instructions, 205 assignments across three pages, rate limiting, expiry, malformed neighbors, changes/removal/restoration, warm page reuse, and course-list disappearance. SQLite checks confirm failure cannot remove prior coursework. Historical checks cover explicit available/completed course-state filters, pagination, restricted entries, failed-discovery retention, and independent current/final grade claims.
- **Materials:** 17 passing tests cover fake network/DNS/redirect/robots/feed/GitLab responses, byte and concurrency limits, local cache reuse, actual PDF text extraction, and generated DOCX/PPTX/XLSX documents. OCR gating uses an injected adapter; it is not a live OCR result.
- **Application:** the connectors are wired through the ingestion coordinator to storage and refresh scheduling. Full application, renderer, MCP, and timing evidence is tracked in [implementation status](implementation-status.md); component tests alone do not establish that complete journey.

Live work still needed includes a successful app-owned UW session, session expiry/reconnect, actual rate-budget behavior, broad course/site formats, real download hosts, feed availability after session expiry, GitLab authentication, and cold/warm first-use timings. Canvas page reads may have server-side viewing effects: whether the selected API calls satisfy `must_view` requirements remains unresolved. Ben accepts incidental viewing/completion effects from reading content. A teacher-controlled test course is unavailable; this uncertainty does not block reading accessible page bodies. GET-only access prevents submit/enroll/post actions; it does not promise absence of server access logs or viewing effects.

## Academic history boundary

Canvas active and completed enrollment catalogs are enumerated independently. The historical query explicitly includes available and completed course workflow states because the student API default includes only available courses. Active learning stays ahead of historical discovery. Old courses contribute metadata and the current student's grade claims; they are not automatically crawled for every old material, and a local inclusion choice cannot override restricted access or this metadata-only historical refresh.

Current/final letters and percentages remain separate. The transient viewer ID checks ownership and is discarded. A failed catalog read preserves prior courses; absence can establish removal only after both catalogs complete. Exact cross-source comparison with enrollment/history/DARS is described in [planning integration](planning-upgrade.md). These records do not establish an official transcript, earned credit, or mastery. Historical course-grade metadata is not projected into hosted/MCP context by this change.
