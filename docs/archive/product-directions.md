# Six organizing concepts

Earlier proposals, September 26, 2026. **Superseded for Home entry and navigation by [Home and visual direction](../home-design-direction.md).** Retained as exploration history. Each changes the primary unit of organization and the normal entry point, not merely the sidebar or colors. They all retain source evidence, course policy, local ownership, correction, and the ability to use existing apps.

Reference roles and inspection limits are in [reference-driven design](../reference-driven-design.md). A named reference supplies a mechanism to investigate, not evidence that students prefer this proposal.

## 1. The day — organize by time

**Feels like:** open the app and see today, with upcoming fixed commitments and unfinished work nearby. One action takes each item into prep, work, or review. Return to the day after finishing.

**Thesis fit:** takes away daily sorting and makes spare time usable for learning. The same course object can appear before class, after feedback, or before an exam without creating duplicate tasks.

**Main risk:** becoming a nicer deadline list; undated learning and long projects become secondary. False schedule precision can add stress.

**References:** Canvas Planner/List View for chronological entry; suggested apps for a small set of useful actions.

**Quick test:** with the same mixed-course dataset, ask “I have 25 minutes before class; what should I do?” and then find an undated reading. Observe whether the student reaches useful practice and can explain incomplete source coverage.

## 2. The workspace — organize by the thing being worked on

**Feels like:** choose an essay, project, exam, or personal goal. Its materials, conversations, app windows, and unfinished work resume together. The space persists across days.

**Thesis fit:** removes the cost of reconstructing context and builds on familiar work tools. Practice can sit beside the assignment that gives it meaning.

**Main risk:** students end up maintaining spaces or choosing from too many resources. A useful task container can become an elaborate file manager.

**References:** Arc Spaces for context switching; Drive shortcuts for references to originals; VS Code workbench as an architecture analogy.

**Quick test:** interrupt work on an essay with a second course task, then resume. Count rediscovery steps, unnecessary windows, and corrections to the selected materials. Include a resource the system initially misses.

## 3. The course — organize by a familiar place

**Feels like:** enter one of your classes. The room already contains its next session, current work, material, policies, and practice. Cross-course search and a compact overview remain available.

**Thesis fit:** makes “my professor, my class” tangible and keeps expectations and terminology close to every action.

**Main risk:** recreating LMS silos and making workload conflicts across classes hard to see. Dense course rooms could bury the next useful action.

**References:** Canvas course cards for familiar entry; Notion object views for different projections of the same course material.

**Quick test:** compare a first visit to an unfamiliar course with planning a week containing three simultaneous deadlines. Watch where class-based navigation helps and where it forces repeated switching.

## 4. The outcome — organize by what the student wants to become ready for

**Feels like:** choose “prepare for this exam,” “make this argument convincing,” or “understand this concept.” The workspace assembles evidence, a short path, and the next useful practice. It remembers progress toward that outcome.

**Thesis fit:** learning is the first thing seen. Coursework and sources explain what good looks like instead of becoming the headline.

**Main risk:** inventing readiness or imposing a study plan before there is enough evidence. Students who know what they want may resent diagnostics or a prescribed sequence.

**References:** artifact-style working surfaces for persistent practice; Learn Git Branching as a candidate for inspectable changes and feedback. Their learning effectiveness for our task is untested.

**Quick test:** use one course with past exams and another without them. Ask for preparation and allow immediate skipping of a diagnostic. Check whether students understand both the useful next step and the limits of the readiness evidence.

## 5. The library — organize by connected evidence

**Feels like:** a course-aware library that has already collected and linked the syllabus, spec, lecture, rubric, and clarification. Open an item or search a short phrase; move from the evidence into work or practice.

**Thesis fit:** directly removes context uploading and makes “it already knew” inspectable. Multiple tasks can reuse one source without duplication.

**Main risk:** students still have to decide what to do, and the product looks like another document repository. A visible graph could add clutter without helping retrieval.

**References:** Drive's resource organization and shortcuts; Notion's multiple views over the same objects. A graph is optional, not the organizing requirement.

**Quick test:** find the actual requirements when Canvas has an empty description and a PDF is stale. Then start useful practice from the correct source. Measure retrieval and decision effort, not document count.

## 6. The companion — organize around the student's current activity

**Feels like:** keep working in the browser, editor, or PDF viewer. Invoke a small control for “what does this mean?” or “pull up what I need.” A full workspace is available for inspection and planning, but normal entry is from the current activity.

**Thesis fit:** supports existing study habits with very little navigation. Context is assembled at the moment help is wanted.

**Main risk:** unclear capture boundaries, accidental voice activation, hidden state, and weak discoverability. Minimal visible UI can conceal complexity rather than remove it.

**References:** Claude quick entry for explicit invocation/window selection; suggested apps for contextual actions. Ambient listening remains a separate unproven choice.

**Quick test:** work in a PDF and then a publisher site. Invoke help, correct a mistaken course, inspect what would be shared, cancel, and return to work. Compare against opening the full app; do not use continuous screen capture as a silent shortcut.

## Compare the concepts fairly

Use the same clearly synthetic mixed-course content, neutral visual treatment, and core tasks: start useful work, find a hidden requirement, get allowed help, switch context, understand stale evidence, and recover from a wrong link. Record student effort and interpretation, plus what each concept makes hard. Keep feasibility, learning value, uncertainty, and clutter separate. Start with inexpensive flows; do not build six full applications or perform model-scored voting to settle Ben's taste.

Ben can reject, combine, or propose another direction after seeing the differences. The current Today implementation is available infrastructure, not a prior decision that concept 1 wins.
