# Design-system research and adopted mechanisms

Inspected September 26, 2026. This is a bounded primary-source review, not an exhaustive survey or evidence that our system has been adopted successfully. The common deliverable name used by the sources is **design system**. Here the governing principles serve as its constitution; images, tokens, patterns and behavioral evidence make it usable.

| Inspected primary source | Mechanism adopted here | What does not transfer / test |
| --- | --- | --- |
| [IBM Carbon button usage](https://carbondesignsystem.com/components/button/usage/) | Separate when-to-use, variants, anatomy, states and implementation/accessibility evidence. Published examples explicitly distinguish maturity. Our recipes now need selection and behavior, not just appearance. | Carbon's visual style and page-wide action limits do not override optional independent briefing actions. Check the grouped review/handled example against its job. |
| [Atlassian color foundations](https://atlassian.design/foundations/color/) | Name tokens by semantic role, emphasis and state; distinguish identity accents from success/error meanings. Our fill/ink pairing and role table apply this. | Their blue brand and full token inventory are not ours. Test a course-color change without changing action/status meaning. |
| [GOV.UK contribution criteria](https://design-system.service.gov.uk/community/contribution-criteria/) | Require usefulness and non-duplication before adding a pattern; report the contexts in which usability and versatility were tested. Our contribution rule and coverage map prevent a screenshot from becoming a universal standard. | Their service aesthetic and organization-scale governance would add unnecessary machinery here. One isolated agent trial is not representative user research. |
| [W3C text contrast explanation](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) | Use measurable minimum contrast and text-size qualifications, then inspect real type and backgrounds. | These explanatory pages support applying WCAG; one palette test cannot certify a product. |
| [W3C target-size explanation](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) | Separate visible glyph size from target geometry; preserve inline-link and spacing exceptions accurately. | Do not enlarge every inline citation into a 24px badge. Test adjacent targets and keyboard access. |

The adopted approach is deliberately smaller than an enterprise component catalog. The alternative of importing a complete external UI skill was considered and rejected: it carries irrelevant aesthetic defaults and obscures the user's controlling choices. Conversely, a brand board plus tokens cannot express return state, evidence freshness or learning claims. A compact governing page plus on-demand recipes and state evidence fills that gap.

[Reference selection](reference-selection.md) records Emil, other craft references, Apple, shadcn and the supplied skill collection, including source pins, useful mechanisms and limitations. This pass did not rewatch all media or visually review all 80 supplied image files. A new reference gets one named job and an actual inspected property before influencing implementation.
